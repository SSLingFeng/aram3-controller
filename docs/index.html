Aram3 网页端服务器控制器

基于 Windows 10 / Windows Server 的多实例 Arma 3 专用服务器（AppID 233780）管理平台： JDK 21 + Spring Boot 4 后端，Vue3 + Element Plus 前端，SQLite 落盘； SteamCMD 真实账号更新本体与 Workshop 模组，PBO 地图上传，结构化启动命令 + RCON 运维（踢人/广播/定时启停）。

AppID 233780 Steam 真实账号 Workshop 模组 PBO 地图 RCON 运维 Vue 3 + Element Plus SQLite

1. 项目概述

背景、定位与命名约定

本项目目标是在一台 Windows 主机上，用浏览器统一管理多套游戏服务器实例（下称 Aram3 实例）。每个实例拥有独立的配置目录、端口、地图（PBO）与模组加载清单， 但共享同一套游戏服务器本体（SteamCMD / AppID 233780）。

管理员通过 Web 控制台添加用户、分配角色与实例级操作权限；被授权用户可执行地图 PBO 上传/下载、 模组 Workshop 同步、结构化启动命令编辑、进程启停（手动/定时），以及通过 RCON 踢人、广播。 底层操作通过 PowerShell（自动探测 5/7）或 SteamCMD 进程完成，输出流式回传到前端。

已确认：AppID = 233780；SteamCMD 必须真实账号登录（匿名不可用）； 地图为 PBO 上传；模组全部 Workshop 自动下载；启动命令采用结构化字段 + 附加参数； 需要 RCON（踢人/广播）与定时/手动启停；备份范围为项目自身数据（库与配置），不备份游戏本体。
平台

Web 管理面

Vue3 + Element Plus，桌面优先，兼顾大屏运维工效；关键操作二次确认与审计。

执行面

进程与 CLI

PowerShell 5/7 + SteamCMD + 游戏服务进程，统一任务队列、日志与超时控制。

数据面

SQLite 落盘

单文件库便于备份迁移；文件类资产（地图/模组）走磁盘存储 + 元数据表。

2. 目标与范围

In Scope / Out of Scope

2.1 必须实现（P0）

  • 多实例：基于配置根目录的子目录隔离；实例可独立启停与配置。
  • 多用户：管理员创建账号；登录鉴权；会话管理。
  • 权限：系统级权限（用户/系统设置）+ 实例级细粒度权限（地图、模组、配置、启停、日志、RCON 等）。
  • SteamCMD（真实账号）：AppID 233780 本体下载/更新/校验；Workshop 模组下载；输出可查看；本体多实例共享。
  • 地图：PBO 文件上传、下载、删除、绑定实例。
  • 模组：按 Workshop ID 自动下载/更新/删除；区分仅服务端加载（serverMod）与双端加载（mod）。
  • 启动配置：结构化字段（端口、profile、mod/serverMod 列表、地图等）+ 附加参数。
  • RCON：踢人、广播；在线玩家列表（若协议支持）。
  • 进程启停：手动启停 + 定时启停（cron 式计划）。
  • PowerShell 调用：自动探测 PS 7 → PS 5，命令执行与 stdout/stderr 回显。
  • 项目数据备份（SQLite + 配置/元数据），不含游戏本体大文件。
  • 操作审计与任务日志。

2.2 建议实现（P1）

  • WebSocket 实时日志 / 控制台。
  • 仪表盘（实例概览、任务、资源占用）——可选项，非必须。
  • 配置文件在线编辑（server.cfg / basic.cfg）与历史版本。
  • 定时自动更新游戏本体。

2.3 暂不纳入（P2 / Out）

  • 集群多机调度、容器化部署。
  • 游戏内反作弊 / BattleEye 策略深度集成（仅保证 RCON 可用）。
  • 游戏服务器本体备份。
  • 本地上传模组（若 Workshop 全覆盖，可不做手动包安装）。
  • 移动端原生 App。

3. 总体架构

分层、运行时拓扑与系统集成

3.1 技术栈

层 选型 说明
运行时 JDK 21（LTS） Windows 10 / Windows Server；虚拟线程可选用于任务并发
后端框架 Spring Boot 4 Web、Validation、Security、WebSocket、Scheduling
数据访问 Spring Data JDBC 或 MyBatis-Plus SQLite；避免强依赖 JPA 方言；单文件库 + WAL
鉴权 Spring Security + JWT（Access + Refresh） 接口鉴权 + 方法级 @PreAuthorize；实例权限在服务层二次校验
进程执行 ProcessBuilder + 超时/取消 PowerShell、SteamCMD、游戏服务进程；统一任务队列
实时通道 WebSocket / SSE 任务进度、服务器日志流、控制台输出
前端 Vue 3 + Element Plus + Vite + Pinia TypeScript 建议；布局：侧栏导航 + 实例切换器
文件存储 本地磁盘目录约定 地图、模组、配置、日志、备份分目录；表中只存元数据与路径

3.2 运行时拓扑

3.3 PowerShell / SteamCMD / RCON 调用策略

  • PowerShell 探测顺序：优先 pwsh.exe（PowerShell 7），失败则回落 powershell.exe（5.1）；启动时写入系统设置并允许管理员手动覆盖。
  • 执行模型：统一 CommandJob（命令、工作目录、环境变量、超时、是否交互）；stdout/stderr 按行推送到任务日志与 WebSocket。
  • 安全：禁止任意 shell 拼接用户输入；参数白名单 + 转义；实例路径由后端根据 ID 解析，不接受客户端任意绝对路径。
  • SteamCMD（真实账号）： 匿名登录不可用。使用 +login <steam_user> <steam_pass>（密码支持 Steam Guard / 令牌需可配置）。 本体更新：+force_install_dir <path> +app_update 233780 validate +quit。 Workshop 模组：+workshop_download_item <workshop_app_id> <workshop_id> （Arma 3 创意工坊条目通常挂在 AppID 107410，下载后迁移/链接到模组库）。 账号密码使用可逆加密（如 Windows DPAPI / 主密钥 AES）存库或系统设置，禁止明文日志。
  • 游戏进程：Windows 下直接启动 arma3server_x64.exe 并附加结构化参数；不长期挂在 PowerShell 会话里。
  • RCON：按实例配置 RCON 地址/端口/密码（BattlEye RCON 或兼容协议）；能力：踢人、广播、拉取玩家列表。所有 RCON 操作写审计。
  • 定时启停：调度器（Spring Scheduling）读取 instance_schedule，到点创建启停任务；支持时区与启用/停用。
人机工效提示：所有命令任务页都要有「运行中 / 成功 / 失败 / 取消」状态、耗时、完整日志下载按钮； 危险操作（删除模组、覆盖地图、更新本体）必须二次确认并写审计。

M2

实例管理

实例 CRUD、根目录、端口、profile、状态机、手动启停、结构化启动命令 + 附加参数。

M3

M4

5. 权限模型

系统权限 + 实例级细粒度权限

采用 RBAC（系统菜单/功能） + 实例 ACL（数据范围） 双层模型。 系统权限决定「能不能进这个功能页」；实例 ACL 决定「对某个实例能不能做某事」。

6.3 关联说明

  1. 用户 ↔ 角色：多对多（sys_user_role）；角色 ↔ 系统权限多对多（sys_role_permission）。
  2. 用户 ↔ 实例：多对多，但带权限位（user_instance_perm）；一人可管多实例，一实例可被多人分管不同能力（含 can_rcon / can_schedule）。
  3. 实例 ↔ 地图（PBO）：多对多（instance_map）；额外 is_active 标记当前地图。
  4. 实例 ↔ 模组（Workshop）：多对多（instance_mod）；关联表承载 load_type / enabled / load_order。
  5. 模组下载：mod_catalog.workshop_id → SteamCMD workshop_download_item；可被多实例复用。
  6. Steam 账号：steam_account → game_server_install.steam_account_id；真实账号，凭据加密。
  7. 本体共享：game_server_install 系统级单例；AppID 233780；实例不拥有本体副本。
  8. 定时启停：instance_schedule 1:N 于实例；到点生成 job_task(SERVER_START/STOP)，与手动启停同管道。
  9. 备份：backup_record 只覆盖项目库与配置元数据，不含游戏本体。

-- 系统用户
CREATE TABLE sys_user (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  username TEXT NOT NULL UNIQUE,
  password_hash TEXT NOT NULL,
  display_name TEXT,
  email TEXT,
  status INTEGER NOT NULL DEFAULT 1,
  is_super_admin INTEGER NOT NULL DEFAULT 0,
  last_login_at TEXT,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);

CREATE TABLE sys_role (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  code TEXT NOT NULL UNIQUE,
  name TEXT NOT NULL,
  description TEXT,
  is_system INTEGER NOT NULL DEFAULT 0,
  created_at TEXT NOT NULL
);

CREATE TABLE sys_user_role (
  user_id INTEGER NOT NULL REFERENCES sys_user(id) ON DELETE CASCADE,
  role_id INTEGER NOT NULL REFERENCES sys_role(id) ON DELETE CASCADE,
  PRIMARY KEY (user_id, role_id)
);

CREATE TABLE sys_role_permission (
  role_id INTEGER NOT NULL REFERENCES sys_role(id) ON DELETE CASCADE,
  perm_code TEXT NOT NULL,
  PRIMARY KEY (role_id, perm_code)
);

CREATE TABLE game_instance (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  code TEXT NOT NULL UNIQUE,
  name TEXT NOT NULL,
  description TEXT,
  root_path TEXT NOT NULL,

  steam_query_port INTEGER,
  rcon_host TEXT,

  updated_at TEXT NOT NULL

  can_transfer_files INTEGER NOT NULL DEFAULT 0,
  can_view_logs INTEGER NOT NULL DEFAULT 1,
  can_rcon INTEGER NOT NULL DEFAULT 0,
  can_schedule INTEGER NOT NULL DEFAULT 0,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL,
  UNIQUE (user_id, instance_id)
);

7. 核心流程

关键业务路径

7.1 启动一个实例（手动 / 定时）

  1. 权限校验 can_start_stop（定时触发时跳过用户权限，记 trigger_type=schedule）。
  2. 读取结构化字段（端口、profile、地图、mod/serverMod 列表）+ extra_args，组装启动命令：
    arma3server_x64.exe -config=... -port=... -profiles=... -mod=<BOTH> -serverMod=<SERVER_ONLY> <extra_args>
  3. 生成 server_runtime，创建 job_task(SERVER_START)。
  4. 启动进程，绑定日志；状态 STARTING → RUNNING。
  5. WebSocket 推送；失败则 ERROR 并保留日志。

7.2 SteamCMD 更新本体 / 下载 Workshop 模组

  1. 使用 真实 Steam 账号（加密凭据）登录；匿名不可用。
  2. 本体：+app_update 233780 validate；模组：+workshop_download_item 107410 <id>。
  3. 检查占用策略（有实例运行时禁止更新本体 / 警告继续）。
  4. 解析进度 → job_task；更新 game_server_install / mod_catalog 状态。
  5. Workshop 下载完成后链接/迁移到 storage/mods，供多实例复用。

7.3 模组管理与双端区分

  1. 录入 Workshop ID → 自动创建 mod_catalog 并触发下载任务。
  2. 绑定实例时选择 load_type：SERVER_ONLY → -serverMod；BOTH → -mod。
  3. 更新/删除模组走任务队列；删除时检查是否被实例引用。

7.4 RCON 与定时计划

  1. RCON：连接实例 RCON → 玩家列表 / 踢人 / 广播；权限 can_rcon；全量审计。
  2. 定时：编辑 instance_schedule（cron + 时区）；调度器到点入队启停任务，与手动同管道。
  3. 项目备份：导出 SQLite + 配置元数据到 storage/backups（不含游戏本体）。

7.5 PowerShell 任务

  1. 选择实例上下文 → 运行受控脚本模板（非自由 shell，防注入）。
  2. 任务中心展示实时输出；可取消。
  3. 所有执行写审计（谁、何时、何实例、何命令模板）。

11. 风险与约束

  • Steam 真实账号安全：密码/令牌必须加密（DPAPI/AES）；禁止明文日志；建议专用小号；Steam Guard 令牌需可轮换。
  • Workshop 与本体 AppID：本体 233780；创意工件通常走 107410。下载失败需账号权限/地区/订阅可见性排查。
  • Windows 进程与文件锁：更新本体或覆盖模组时若服务器占用文件会失败；需要停止实例或维护窗口。
  • PowerShell 执行策略：部分机器 Restricted；优先 pwsh -NoProfile / -Command，避免依赖脚本执行策略。
  • SQLite 并发：开启 WAL；写操作串行化关键任务；避免多进程狂写。
  • 路径穿越：文件名/路径由服务端白名单映射，拒绝 .. 与绝对路径注入。
  • 大文件 PBO 上传：分片或限流、校验磁盘空间、上传完再入库。
  • RCON 协议差异：BattlEye RCON 与其它实现细节不同；踢人/广播需适配并做超时与重连。
  • 定时启停冲突：计划与手动并发时用实例级锁；失败要告警而不是静默。
  • Spring Boot 4 兼容：确认 starter/驱动与 Boot 4 / Jakarta 兼容矩阵。
  • 权限误配：高危位（RCON、启停、本体更新、Steam 账号）默认关闭。
